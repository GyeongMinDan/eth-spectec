# Consensus-SpecTec

Spec-guided test generation proceeds in four steps.

## 1. Seed Preparation
First, the official tests are supplied in SSZ format. To run them against the SpecTec interpreter, they must first be converted to JSON format.
Three different directories contain state transition test cases: `sanity/blocks`, `random`, and `finality`.
We convert them each.
```sh
# Convert sanity block tests
python3 Converter/generate_json_test_cases.py \
  Converter/OfficialTestSuite/capella/sanity/blocks/pyspec_tests \
  --fork capella \
  --output-dir capella-tests -v
# Convert random tests
python3 Converter/generate_json_test_cases.py \
  Converter/OfficialTestSuite/capella/random/random/pyspec_tests \
  --fork capella \
  --output-dir capella-tests -v
# Convert finality tests
python3 Converter/generate_json_test_cases.py \
  Converter/OfficialTestSuite/capella/finality/finality/pyspec_tests \
  --fork capella \
  --output-dir capella-tests -v
```
For multi-block inputs, the converter runs the result of `eth2spec` to generate `post.json`.
For invalid test cases (marked with the `invalid` prefix), the error message of `eth2spec` is saved as `error.txt`.

## 2. Baseline Coverage
Next, we measure premise coverage on the baseline tests, generated by the previous command.

```sh
nohup ./spectec-core eth coverage -v \
  --spec-dir spec/spec_capella \
  --test-dir capella-tests \
  --checkpoint capella-baseline.ckpt \
  --save-interval 1 \
  --node-coverage.level full \
  --no-validate \
  --max-slot-gap 32 \
  --node-coverage.output capella-baseline.txt
```

This may take around 2~3 hours. We provide the pre-computed baseline coverage as a reference in `testgen_data/capella/novalidate/baseline.ckpt` and `baseline.txt`. The checkpoint file is a serialized file including information on which test inputs covered which premises, which is later used by the test generator.

The baseline coverage reveals a set of never-falsified premises, from which we must manually filter out tautologies, closing branches, and out-of-scope premises. Here, we provide a pre-audited set of target premises, located in `testgen_data/capella/target_premises.txt`.

## 3. Test Generation
In addition to the spec, the test generator expects a baseline coverage checkpoint file (`.ckpt`), a directory containing the seeds, and a file of target premises.
```sh
./spectec-core eth testgen \
  --spec-dir spec/spec_capella \
  --coverage testgen_data/capella/basline.ckpt \
  --premises-file testgen_data/capella/target_premises.txt \
  --test-dir capella-tests \
  --output capella-testgen \
  --coverage-level 7
```
This process runs for 1~2 hrs.

### 3-2. Convert JSON to SSZ
The generator outputs JSON test cases by mutating the JSON seeds. To run them through the differential testing environment, they must be converted back to SSZ format.
```sh
python3 convert_testgen_json_to_ssz.py \
  --input-dir ./capella-testgen \
  --fork capella \
  --output-dir ./capella-testgen-ssz
```

### 3-4. Filter illformed JSON
Some JSON tests may not survive the SSZ conversion. This happens when SSZ expects a vector (array of fixed length), but the test generator generates arrays of different lengths. As these tests are invalid from the client and spec's point of view, they must be filtered out for a fair comparison.
```bash
python3 filter_tests.py capella-testgen capella-testgen-ssz/testgen/spectec-generated capella-testgen-filtered
```

### 3-5. Measure Testgen Coverage
Finally, we can measure the coverage of the generated tests:
```bash
nohup ./spectec-core eth coverage -v \
  --spec-dir spec/spec_capella \
  --test-dir capella-testgen-filtered \
  --checkpoint capella-testgen.ckpt \
  --save-interval 1 \
  --node-coverage.level full \
  --no-validate \
  --max-slot-gap 32 \
  --node-coverage.output capella-testgen.txt
```
This process may run for up to 240 hrs. We add several utility features to mitigate the load:
```bash
# Merge the coverage information of two checkpoints
./spectec-core eth checkpoint merge file1.ckpt file2.ckpt \
  --output file1+2.ckpt \
  --spec-dir spec/spec_capella
# View the coverage report of a checkpoint
./spectec-core eth checkpoint report capella-testgen.ckpt \
  --node-coverage.level full \
  --spec-dir spec/spec_capella
```
The `--save-interval` flag adjusts the interval in which intermediate coverage information is saved to the `--checkpoint` file. One can also resume coverage measurement on a checkpoint by adding the `--resume intermediate.ckpt` flag.
Note that splitting and merging checkpoints may affect the hit count, but it does not affect the boolean value of hit/miss.
